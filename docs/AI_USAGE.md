# AI usage and disclosure

## How AI was used in this project

* **Code, tests, evaluation harness, documentation and the React UI were written with Claude** (Anthropic)
  in a single working session, from the assignment brief.
* Every piece of generated code was **executed** in the build environment before it was accepted: the
  pytest suite (88 tests), the evaluation harness on a 72-file dataset, a production build of the UI, and
  an automated browser session that uploaded files, reviewed a record, saved a correction and searched.
* Several defects were found by running this work, not by reading it. They are listed in
  `docs/EVALUATION.md`, section 4.
* The **runtime system** does not depend on AI by default. Rule-based extraction runs with no model. The
  optional LLM extractor (`ANTHROPIC_API_KEY`) is off unless configured, and its output is grounded (see
  below).

## AI prompts used inside the product

### LLM extraction system prompt (`backend/app/extraction.py`, `LLM_SYSTEM`)

```text
You extract invoice data. Reply with ONE JSON object and nothing else. Keys: invoice_number, invoice_date (YYYY-MM-DD), supplier_name, customer_name, subtotal, tax, total (numbers, no thousands separators), currency (ISO 4217), line_items (array of {description, quantity, unit_price, amount}). Use null for anything not explicitly present. Never guess or compute.
```

User message template (the document text is inserted between the markers, truncated to 30,000 characters):

```text
Invoice text:
<<<
{document text}
>>>
```

Model: `DI_LLM_MODEL` (default `claude-haiku-5-5`). `max_tokens` 1500. Temperature not set (provider default).

### Guardrails around the model output

1. The reply must contain one JSON object; anything else falls back to rules.
2. Each value is accepted only if its literal form occurs in the source text (`_grounded`). Otherwise it is
   discarded and recorded as a warning, e.g. `llm_value_discarded:total`.
3. Numeric fields are parsed with the same amount parser as the rules. Currency must be a known ISO code.
4. Any HTTP, timeout or parsing error falls back to the rule-based result, with a warning.

## Prompts used to build this project

The brief was used as the starting prompt. Development then proceeded in one session through iterative
requests to implement each task, to run the tests and evaluation, and to fix what they reported.

## Disclosure statement

This project was built with the assistance of Claude (Anthropic), an AI model, in a single working session.

Claude generated the initial implementation: the FastAPI backend, the document-processing pipelines (PDF, OCR, spreadsheet and CSV), the extraction and validation rules, the background job runner, the search layer, the React interface, the test suite, the evaluation harness and dataset generator, and the documentation. The work was carried out on request, with each step checked by running it.

Everything was verified by execution rather than accepted on inspection: the 88-test pytest suite, the evaluation over a labelled 72-file dataset, a production build of the interface, and an automated browser session that uploaded files, reviewed and corrected a record, and searched. Several defects were found this way and fixed; they are listed in docs/EVALUATION.md, section 4.

The author provided the assignment brief and directed each step of the work, including requests to implement each task, to run the tests and evaluation, and to fix what they reported. Claude carried out the implementation.

Limitations to note: the evaluation uses synthetic data generated by the project's own templates, so its figures do not measure accuracy on real invoices. The optional LLM extraction path was not run against the live API.
